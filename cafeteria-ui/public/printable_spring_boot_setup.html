SPRING BOOT BACKEND SETUP

1. Introduction

This document describes the initial Spring Boot backend setup for the Cafeteria Management System (BiteFlow): the project structure, the PostgreSQL database connection, and the JPA entity classes that map to the tables defined in the system specifications. It follows the architecture specified in the SRS — Spring Boot 3.x with Spring Security, Java 17+, and Java Persistence API (JPA) for database access.

The backend runs on port 8080 and is designed to be consumed by the React.js frontend running separately on port 8081, communicating over secured REST APIs with JWT authentication and role-based access control (RBAC) for customer, cashier, chef, nutritionist, manager, and admin roles.

3. PostgreSQL Connection Setup

The database connection is configured in application.yml using environment variables for credentials, so secrets never need to be hard-coded or committed to source control.

3.1 Database and role creation

Run once, as a PostgreSQL administrator, before starting the application for the first time:

-- ===========================================================
-- BITEFLOW - PostgreSQL initial setup
-- Run once, as a PostgreSQL admin, before starting the app.
-- Hibernate (ddl-auto: update) will create the actual tables on first run.
-- ===========================================================
CREATE DATABASE cafeteria_db
  WITH ENCODING 'UTF8'
  LC_COLLATE = 'en_US.UTF-8'
  LC_CTYPE = 'en_US.UTF-8';

CREATE USER cafeteria_user WITH PASSWORD 'cafeteria_password';
GRANT ALL PRIVILEGES ON DATABASE cafeteria_db TO cafeteria_user;

4.1 User.java

package com.cafeteria.entity;

import jakarta.persistence.*;
import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.NotBlank;
import lombok.*;
import java.time.LocalDateTime;

@Entity
@Table(name = "users")
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank
    @Column(unique = true, nullable = false, length = 50)
    private String username;

    @Email
    @NotBlank
    @Column(unique = true, nullable = false, length = 100)
    private String email;

    @NotBlank
    @Column(name = "password_hash", nullable = false, length = 255)
    private String passwordHash;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 30)
    private Role role;

    @Column(name = "employee_id", length = 20)
    private String employeeId;

    @Column(name = "dietary_restrictions", columnDefinition = "TEXT")
    private String dietaryRestrictions;

    @Builder.Default
    @Column(name = "created_date", nullable = false, updatable = false)
    private LocalDateTime createdDate = LocalDateTime.now();

    public enum Role { CUSTOMER, CASHIER, CHEF, NUTRITIONIST, CAFETERIA_MANAGER, ADMIN }
}

4.2 MenuItem.java

package com.cafeteria.entity;

import jakarta.persistence.*;
import jakarta.validation.constraints.DecimalMin;
import jakarta.validation.constraints.NotBlank;
import lombok.*;
import java.math.BigDecimal;

@Entity
@Table(name = "menu_items")
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class MenuItem {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank
    @Column(nullable = false, length = 200)
    private String name;

    @NotBlank
    @Column(nullable = false, length = 100)
    private String category;

    @Column(columnDefinition = "TEXT")
    private String description;

    @DecimalMin(value = "0.0", message = "Price must be positive")
    @Column(nullable = false, precision = 8, scale = 2)
    private BigDecimal price;

    @Column(nullable = false)
    private Integer calories;

    @Column(columnDefinition = "TEXT")
    private String allergens;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "chef_id")
    private User chef;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private Status status = Status.DRAFT;

    public enum Status { DRAFT, ACTIVE, INACTIVE, SEASONAL }
}

4.3 Order.java

package com.cafeteria.entity;

import jakarta.persistence.*;
import lombok.*;
import java.math.BigDecimal;
import java.time.LocalDateTime;

@Entity
@Table(name = "orders")
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class Order {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "customer_id", nullable = false)
    private User customer;

    @Builder.Default
    @Column(name = "order_date", nullable = false)
    private LocalDateTime orderDate = LocalDateTime.now();

    @Column(name = "total_amount", nullable = false, precision = 10, scale = 2)
    private BigDecimal totalAmount;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private Status status = Status.PENDING;

    @Enumerated(EnumType.STRING)
    @Column(name = "payment_method", nullable = false, length = 30)
    private PaymentMethod paymentMethod;

    public enum Status { PENDING, PREPARING, READY, COMPLETED, CANCELLED }
    public enum PaymentMethod { CASH, CARD, DIGITAL_WALLET, MEAL_PLAN }
}

5. Design Notes

  • Primary Keys: Every entity uses an auto-incrementing `Long` surrogate primary key (`GenerationType.IDENTITY`), ensuring high index lookup speeds and standard clean schema mappings.
  • Enums Strategy: All enum mappings (such as `Role`, `Status`, and `PaymentMethod`) are saved to the database as human-readable string values via `@Enumerated(EnumType.STRING)`, protecting the persistence layer from ordering revisions in Java.
  • Lazy Loading: Relationships are mapped to FetchType.LAZY by default to avoid triggering heavy nested joins when returning payloads.
  • Audit Logs Immutability: AuditLogs records are append-only to satisfy security and audit trail regulations (§3.5); no update or delete REST controllers are exposed in the service layer.
  • Allergen & Diet Details: Allergen lists and dietary restriction exclusions are stored in PostgreSQL using text columns mapped to JSON serialization wrappers to allow fast parsing of variable parameters on the React UI front-end.
